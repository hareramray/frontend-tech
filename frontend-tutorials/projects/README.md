# Guided frontend projects

[Curriculum](../README.md) · [Roadmap](../ROADMAP.md)

These are build-along guides with starting code, implementation steps, failure scenarios, and completion criteria. They are not pre-generated applications. Create each project in a separate practice directory and commit completed milestones.

| Project | Focus | Deliverable |
|---|---|---|
| [01. Accessible portfolio](01-accessible-portfolio/tutorial.md) | Semantic HTML, responsive CSS, accessible navigation, media, metadata | A small multi-page site and an accessibility review |
| [02. API dashboard](02-api-dashboard/tutorial.md) | Async state, URL filters, data contracts, sorting, tests | A searchable catalog/dashboard with realistic failure handling |
| [03. Offline notes](03-offline-notes/tutorial.md) | IndexedDB, service-worker lifecycle, persistence, recovery | A local-first notes app with honest storage status |
| [04. Production capstone](04-production-capstone/tutorial.md) | Architecture, framework rendering, server boundaries, quality, delivery | A deployed application with a release and rollback record |

For each milestone, record what you expected, what actually happened, and what evidence proves completion. Keep real credentials and private user data out of tutorial repositories. Complete one project well before adding unnecessary framework or infrastructure complexity.
